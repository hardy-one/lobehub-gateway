### Fixed

- **agent-gateway event replay**: the replay event buffer is now retained by inactivity time (2-hour TTL) instead of being trimmed by count (previous 1000-entry cap, trimmed to 500). A reconnect after a long or high-volume operation no longer silently loses earlier events or reports a false `gap`.
- **agent-gateway terminal status**: finished operations now stay in memory for 2 hours (was 10 minutes) before cleanup, and their terminal status is no longer deleted from SQLite on cleanup. A mobile client that backgrounded the app during a long run can now resubscribe and observe `completed` instead of spinning after its WebSocket was dropped.

### Compatibility

- Matches the upstream `StreamEventManager` retention policy: events are kept until the stream's 2-hour inactivity TTL expires, and are never trimmed by count. The in-memory cleanup window and event-buffer retention now share the same 2-hour value.
- The persisted terminal status is reclaimed only by the existing 24h orphan TTL. `hubQueue` still has a 1000-entry bound as subscriber backpressure; that behavior is unchanged.
- Events are still lost on process restart, and open LLM attempts still use their own shorter replay lifetime. No new configuration is required.
